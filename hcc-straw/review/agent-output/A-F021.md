## Published Next proxy contract

`apps/web/lib/backend-proxy.ts` imports the Next server-only marker and exports:

```ts
export type BackendPath = '/api' | '/api/users' | '/api/projects' |
  `/api/auth/${string}` | `/api/users/${string}` | `/api/projects/${string}`
export async function proxyBackend(request: Request, path: BackendPath): Promise<Response>
```

Route owners use a constant backend path, e.g. `return proxyBackend(request, '/api/auth/login')`, in the Next Node runtime. Rust uses the confirmed /api prefix. Destination is always HTTP literal 127.0.0.1; STRAW_API_PORT is a validated integer 1–65535, default 3001. STRAW_WEB_ORIGIN defaults to http://localhost:3000. It can deliberately select one exact HTTP(S) localhost or 127.0.0.1 origin, with no credentials, path, query or fragment. It never grants wildcard origins. Mutating requests with missing or mismatched Origin receive structured 403 FORBIDDEN_ORIGIN before transport. The configured scheme/host/port must match the browser Origin exactly.

Runtime path validation permits only /api and auth/users/projects paths with alphanumeric, underscore or hyphen segments. Schemes, hosts, slashes encoded through percent escapes, backslashes, dots, traversal, path query/hash injection and unrelated roots are rejected with structured 400 INVALID_PROXY_PATH. The incoming request URL contributes only its query string. Only content-type, cookie and origin request headers pass through; authorization, host and forwarding headers are dropped. Method and body bytes pass through. Redirect following is disabled, caching is disabled and a 30-second timeout applies. Backend status, body, content-type and Set-Cookie pass through, retaining multiple cookies with getSetCookie on the provisioned runtime and a single-header compatibility fallback. Configuration/transport failures return safe 503 SERVICE_UNAVAILABLE envelopes; unreadable incoming bodies return 400 INVALID_REQUEST. This helper performs no session authorization itself; the Rust service validates every credential/role/owner request.

This contract was published to root before completion for forwarding to F007/F009/F008. Browser session hydration and service consumers are separate serialized owners.
