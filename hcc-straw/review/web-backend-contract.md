# Local web service integration contract

User decision: separate Rust/Axum service backed by SQLite. This contract guides minimal implementation; agents report deviations for serialized arbitration.

- Source boundary apps/api is an independent Cargo workspace. Bind literal 127.0.0.1 on a configured local port (default3001); Next browser requests use same-origin /api and server-only proxying to this literal loopback service. Do not introduce an externally reachable listener or arbitrary outbound proxy.
- apps/web/types/index.ts is the wire contract: ApiResponse<T> discriminated envelope, void success {success:true,data:null}, singular success data is the entity, paginated success data is {data:[],meta:{page,limit,total,pages}}. ISO timestamps are JSON strings. AuthResponse is {user}; flags come from persisted state. Errors carry code/message and meaningful HTTP status.
- Session credential is opaque cryptographically random, stored hashed server-side, cookie HttpOnly/SameSite=Strict/path=/; no browser localStorage token. Verify persisted expiry/revocation/user active state on each protected request. Rotate on refresh; logout revokes. rememberMe uses bounded longer expiry and persistent cookie; ordinary sessions omit persistent Max-Age. Secure cookies when serving HTTPS, explicit local HTTP development support.
- Register creates ordinary user role only. Administrative bootstrap is an explicit local operator CLI action, never a public register field. Argon2 password hashing uses provisioned cached crates; never plaintext or fast unsalted hashes. SQLite constraints and transactions enforce duplicate/ownership/concurrency behavior and survive restart.
- Next forwarding helper passes only needed method/body/content-type/cookie/origin, retains backend status/envelope/Set-Cookie, returns structured service-unavailable errors, and cannot accept arbitrary destination URLs. Unsafe methods validate Origin against configured literal local web origin. Missing/malformed credentials return401, role/owner denials403, invalid inputs400, duplicate conflicts409.
- Eight auth endpoint contracts are login/register/logout/me/refresh-token/verify-email/forgot-password/reset-password. Recovery/email delivery have no authorized external transport: explicitly return501 UNSUPPORTED with truthful explanatory UI rather than simulated success or returning secrets. Existing service methods retain those structured failures.
- Users/profile and projects are serialized modules owned A-F009 then A-F008. F007 publishes public router/store/auth helpers for them; keep shared lib.rs lease single-writer. All IDs/roles/pagination/body fields are validated server-side. Minimum supported profile fields match current settings caller; ensure response carries persisted flags and timestamps.
- Offline cache contains axum0.7.9,rusqlite0.31.0,argon2 0.5.3,rand0.8.6,sha2 0.10.9,tower0.5.3; resolve exact available offline dependency graph without fetching. Owners may use compatible cached versions and record them.

This is implementation guidance within the chosen architecture, not a release-readiness claim. Full HTTP/restart/isolation/session verification belongs to owners plus S04. Desktop source scan still blocks release.

Client URL convention: ApiClient baseURL is /api. Service owners call /auth/login, /users, /projects (without a second /api prefix); browser requests resolve /api/auth/login etc. Backend proxy route constants retain full /api/... paths.

Backend core publication (A-F007, pending acceptance; consume only after DONE): cookie name straw_session. apps/api/src/lib.rs exports AppState{store:Store,config:Arc<Config>}, ApiError/ApiResult/success; users/projects router merges occur before fallback/layers/with_state. Store::with_conn mutable Connection closure returning ApiResult; Store::user and store load_user/USER_COLUMNS/user_from_row/db_error/random_id/timestamp/now helpers. UserDto/ProfileDto use persisted snake_case SQLite columns and camelCase serde. auth::authenticate(state,headers)->ValidSession{user}, require_roles and require_owner_or_admin. Canonical backend schema lives store.rs; F009/F008 use shared helpers, not parallel stores.

F024 service contract publication: GET/PUT users/profile return ProfileDto; GET users/:id returns UserDto; collection search/list uses page/limit/search, no /search or offset. Projects collection and item CRUD, PATCH item/archive and item/activate return null void envelope; creates name/description?/status?, updates optional same. Files/avatar return explicit501 UNSUPPORTED locally with no transfer; docs must remove supported-storage claims. F009/F008 must inspect F024 exports and exact payloads after DONE.

A-F006 publication (pending DONE): lib/backend-proxy.ts exports preflightResponse(request:Request,methods:readonly string[]):Response. Each Next route OPTIONS calls with actual supported methods; helper adds OPTIONS, checks exact configured local Origin and requested method/headers, permits Accept/Content-Type only and never wildcard. Actual/error proxy responses receive same allowed-Origin/Vary/credentials policy. Auth route OPTIONS is added under F006 serialized lease; F009/F008 must reuse this helper for each new route.
