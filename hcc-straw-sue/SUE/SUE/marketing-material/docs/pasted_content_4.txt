 SUE AGENT SPECIFICATION
# For AI Assistants (Desktop Commander, GitHub Copilot, etc.)
# ──────────────────────────────────────────────────────────────

## OVERVIEW
SUE (Sovereign Unified Extension) is a browser extension that provides:
- Sovereign AI chat via local Ollama or premium Venice.AI
- Cloud storage status (Koofr, IceDrive, Degoo)
- Project management UI
- Zero telemetry, zero external calls except user's own endpoints

## FILES TO KNOW

### Core Extension Files
- `manifest.json` - Extension metadata, permissions, content scripts
- `background.js` - Service worker, message routing, storage
- `content.js` - Optional content script for page injection
- `sue.html` - Sidebar HTML shell
- `styles.css` - Dark theme, sovereign UI

### Rust Workspace
- `Cargo.toml` - Workspace root with all dependencies
- `sue-core/src/lib.rs` - Shared types, browser APIs
- `sue-view/src/main.rs` - Leptos UI, WASM entry

### Build System
- `package.json` - npm scripts, webpack config
- `webpack.config.js` - Bundle WASM + JS for production
- `wasm-pack` - Rust → WASM compiler

## EXTENSION PERMISSIONS

```json
{
  "permissions": [
    "storage",           // Local user data
    "activeTab",         // Current tab access
    "scripting",         // Inject content scripts
    "tabs",              // Tab management
    "notifications"      // User alerts
  ]
}
```

**Zero** external access. All data stays in browser.

## SECURITY MODEL

### Vault Key Storage
- Generated on first run
- Stored in `chrome.storage.local` as hex
- Never sent to external servers
- Decrypted in-memory only for AES-256-GCM operations

### Content Script Isolation
- Cannot access `localStorage`, `sessionStorage`
- Cannot access `document.cookie`
- Cannot access `parent.window` (if in iframe)
- Only reads: URL, title, user-selected text

### CORS Enforcement
- Only allows: `http://localhost:11434` (Ollama)
- Only allows: `http://localhost:8080` (HCC API)
- Blocks all external endpoints

## EXTENSION LIFECYCLE

1. **Install** → `manifest.json` loaded
2. **Background** → `background.js` service worker starts
3. **User clicks icon** → Sidebar opens
4. **Sidebar loads** → `sue.html` renders
5. **WASM hydrates** → `sue-view.wasm` + `sue-view.js`
6. **UI renders** → Leptos components mount
7. **User interacts** → Messages routed to local APIs

## TROUBLESHOOTING

### "WASM not loading"
- Check `web_accessible_resources` in `manifest.json`
- Ensure WASM file exists in `dist/`
- Verify CORS headers allow extension origin

### "Storage access denied"
- Browser may block in incognito mode
- Add `"incognito": "split"` to `manifest.json`

### "CORS errors"
- HCC API must allow extension origin
- Add header: `Access-Control-Allow-Origin: null`
- Or restrict to `localhost` only

### "Sidebar not appearing"
- Verify `manifest_version: 3`
- Check `sidebar_action` section in `manifest.json`
- Ensure icon files exist
