# STRAW hybrid merge · 2026-10-10

The approved platform consolidation is implemented in the existing STRAW workspace. The original three project trees remain intact. Existing workflow data is retained; legacy product data is not automatically transformed or decrypted.

## Use the bundled coder

1. Build with `cargo tauri build --no-bundle`, or start development with `cargo tauri dev`. Build hooks stage the optimized worker and build the frontend. The model pack must be present before building.
2. Open **Vault and grants**. Create a vault with a passphrase of at least 12 bytes, or unlock the existing vault. The passphrase is not persisted.
3. Open **Local models**. Load the bundled model, then Warm it. Select it for chat and code.
4. Use chat, code generation, workflow execution or the fabricator. The native dialog identifies the operation and request digest; **Approve once** creates a signed grant valid for five minutes. The grant is consumed before the operation starts and cannot be replayed, even if the operation fails.

For an existing local service, select Ollama or llama.cpp, set its literal `http://127.0.0.1:PORT` address, then **Scan models** and **Load and select**. Ollama selection loads an installed model; no pull/download operation is exposed. Discovery excludes cloud tags and remote metadata; selection and desktop generation recheck `/api/show` before sending a prompt. This follows [Ollama's remote model metadata](https://github.com/ollama/ollama/blob/main/api/types.go). A separately installed service remains a trusted companion process: loopback addressing cannot prove how an arbitrary local proxy handles a request. llama.cpp serves the model loaded when its separately started server launches. “Ollama.cpp” has been interpreted as llama.cpp. Newly added LLM workflow nodes inherit the current selected model; saved nodes retain their explicit configuration.

## Shared platform

**Operational v1.0 recovery slice.** The desktop can create an approved, new-folder core recovery copy and verify one offline while locked. A single store-actor operation captures committed WAL data into a standalone SQLite image; security operations remain serialized against the matching checkpoint. A signed manifest binds database bytes and checkpoint bytes to the vault signing identity. Verification checks signatures, file hashes, SQLite integrity/foreign keys and the full signed ledger without migrations. The core copy includes saved workflows, documents, vectors, archives and encrypted vault data, while ordinary data remains plaintext. Records, models, generated files and unsaved UI state require separate preservation. No automatic restore, existing-folder overwrite, release-hold exception or v1.0 readiness claim is introduced. See `../review/sovereign-consolidation-2026-10-10/recovery-validation.md`.

**Digital Hands credential adapter.** Vault now offers a local database picker, owner selection, ID-and-digest preview, encrypted import and separately approved individual reveal. The adapter reproduces the original HKDF-SHA256 domain key and nonce-prefixed AES-256-GCM format using the installation `SECRET_KEY`; account login passwords cannot decrypt this store. All selected fields authenticate before one transaction stores a XChaCha20-Poly1305 archive and its signed ledger receipt. Locked or quarantined vaults, changed source content and incorrect/replayed grants refuse the protected operation. A failed decrypt spends the approved grant but creates no import.

IDs and owner IDs are preserved as decimal strings; text, nullable fields and SQLite timestamp storage classes are copied without trimming or date conversion. This is an operator-controlled copy of one owner's credentials, not a migration of account authentication or access-control policy. Other accounts remain separate imports; account hashes, sessions, documents, workflows and integrations are excluded. Unsupported credential columns, views, invalid field types and oversized batches are rejected. Limits are 1,000 selected credentials, 256 KiB of source fields and 1 MiB of encoded archive. The newest 100 signed receipts are listed. Repeat content keeps its first receipt; existing credentials are never overwritten.

The installation key is supplied only through the masked desktop field and is never loaded from configuration files, persisted or included in consent/ledger digests. Native key and decrypted buffers use managed zeroization; this does not promise forensic memory erasure. Import returns metadata only. Separate Unseal approval reveals one credential for up to 30 seconds, with explicit clear and clearing when this vault panel locks. Browser text already displayed cannot be guaranteed erased. No secret is automatically offered to AI or the read-only browser-sharing service. Ciphertext, owner, IDs, source provenance and import time are checked against signed ledger entries, including while locked. Immutable triggers add application-level protection against updates and deletes.

**Eduba archive adapter.** Documents now offers a local database/JSON picker, a count-and-digest preview, and approved import/export. The five baseline record tables become a separate immutable plaintext snapshot in the shared store. IDs, relationships, sequence values, text and integer timestamps are retained exactly; tables are read within one SQLite transaction, without schema migrations. Existing extra columns in those tables cause rejection rather than silent field loss. Other tables, indexes, migration history and credential tables are not copied. Text fields are copied as written and can contain sensitive information.

Import approval binds both the source path and canonical content digest. Import reads the source again before spending approval and refuses changed content. The owned reviewed snapshot is then inserted idempotently; its immutable digest identifies duplicate content. Export verifies the stored content and binds approval to that digest and the chosen new `.json` file. Exports can be imported again. Archives are limited to 10,000 records and 16 MiB, with the newest 100 listed. This is a logical archival copy, not a replacement live Eduba database, a binary database backup or a credential migration. SQLite immutability triggers and content checks do not authenticate an attacker rewriting both content and digest outside the application.

**Svelte 5 / Tauri / Specta.** Desktop panels now cover documents, vault/grants, model lifecycle, fabricator, workflows, chat and code. One tauri-specta registry drives native dispatch and checked-in TypeScript plus JavaScript wrappers. The UI imports those generated wrappers. Errors have closed codes and messages; attachment counters use u32. `scripts/check-bindings.ps1` detects drift. Rust Svelte compilation emits browser JavaScript; Trunk builds the separate compute crate to WASM. No Node build pipeline is added.

**SQLx / WAL / vectors / CoW.** The workflow engine now uses shared SQLx storage on a dedicated Tokio actor, preserving its synchronous domain APIs without entering a caller's runtime. Existing tables, session ownership and interrupted-run recovery remain. Documents use immutable revisions and optimistic head comparison; stale writes fail. Workflow results can become immutable documents. Vectors persist f32 values and use model/dimension filtering with exact cosine search. Embeddings must be supplied by the caller. CoW means application revisions, not filesystem reflinks; vector search is exact, not ANN.

**Axum / Tower / Tokio.** Browser sharing is disabled at startup and enabled explicitly in Local models. Its API binds only loopback, exposes read routes, retains the fixed PWA-origin check, and applies size/timeout middleware. The Axum update also adapts Eduba's parameter route syntax. Browser origin restrictions do not authenticate local processes.

**Candle worker.** The separate Rust process owns CPU Qwen3 inference; Candle dependencies are isolated behind its worker feature. Tauri starts it on Load, uses bounded typed JSON over stdin/stdout, enforces host deadlines, and kills/joins it on unload or exit. The worker receives a minimal environment. It has no cloud fallback. Status stays Cold until an explicit Load; generation requires Warmed.

**Vault / Gate / Ledger.** Argon2id derives a local vault key from a random salt and passphrase. XChaCha20-Poly1305 encrypts vault items with their identities as associated data. The Ed25519 signing key is itself encrypted in the vault. Native consent issues request-digest-bound, expiring single-use grants for Assist, Export and Unseal operations. Generate includes both Assist and Export. Workflow execution is bound to its complete graph. Atomic consumption and signed ledger insertion precede protected side effects.

The append-only ledger commits to sequence, previous hash, time, operation kind and subject digest. A separately stored signed checkpoint detects database changes or rollback relative to that checkpoint. Startup verification runs while the vault remains locked. Verification failure quarantines writes and protected operations; there is no automatic repair or grant reset. Egress and external escalation remain disabled. Ledger entries contain digests, not raw prompts, secrets or decrypted vault contents. Vault items are never automatically attached to inference. The ordinary document store is plaintext SQLite; sensitive items belong in the encrypted vault.

The checkpoint file is independent of the SQLite database, but both live on the same computer. Preserve a trusted receipt or backup outside that writable machine to detect an attacker replacing both with an older valid pair. SQL commit and checkpoint replacement are separate durability steps; a crash between them causes quarantine rather than silently accepting a changed head. Back up `straw.db` and `straw-checkpoint.json` as a matching pair. No recovery service stores the passphrase.

**Fabricator.** The native Rust controller preserves the original generator's nine template names, embeds reviewed shared engine/storage/security/Axum sources, records provenance hashes and refuses to overwrite existing output. It emits a core service bundle whose read-only loopback service checks its ledger before listening and keeps its vault locked. Template labels do not imply implemented billing, healthcare, financial or other domain features. The original generator's cloud integrations are retained in its source tree and are not enabled by the desktop.

## Model provenance and packaging

The user-selected [rockypod/svelte-coder-4b](https://huggingface.co/rockypod/svelte-coder-4b) pack uses `svelte-coder-v0.9.0-4b-q4_k_m.gguf`. The file is 2,497,280,352 bytes; its SHA-256 matches the publisher's LFS record at revision `7d1d35d80bcd1fdf1052d970e72bb58b9cb9db1f`. Both publisher-supplied licenses accompany it. See `src-tauri/resources/models/svelte-coder/NOTICE.md`.

Loading checks pinned weight/tokenizer digests, every tokenizer vocabulary ID against the GGUF and Qwen3 architecture before constructing the model. Weights stay quantized; CPU activations use F32. Context is capped at 8192 tokens, output at 1500, and inference has a deadline. Disk size does not describe total inference memory. Generated code still requires independent compilation and review.

Weights and tokenizer are staged locally and excluded from Git. Reproduce staging with `scripts/stage-model-pack.ps1 -SourceDirectory PATH`; it requires the pinned hashes. Tauri's resource map includes the model pack; `externalBin` includes `straw-infer`. `scripts/stage-sidecar.ps1 -Release` stages an optimized worker. Runtime downloads are unnecessary.

## Validation and migration boundaries

Final checks and logs are recorded in `../review/sovereign-consolidation-2026-10-10/hybrid-validation.md`. The original review in that directory describes the pre-merge snapshot.

Digital Hands' original project remains intact. Its credential adapter and Eduba's archive adapter copy supported records only on explicit approval; original records remain in their stores. Digital Hands authentication, sessions, workflows and integrations are outside the credential slice. The workflow archive action creates a shared-store immutable document, not an Eduba submission. Adapter receipts are in `../review/sovereign-consolidation-2026-10-10/eduba-archive-validation.md` and `../review/sovereign-consolidation-2026-10-10/digital-hands-validation.md`.

Optional Wasmtime horde execution, mesh/swarm/MCP peers, grammar/tripwire acceptance and remote-provider egress are not enabled. The proposal's first Vault/Gate/Ledger/Engine workbench is the implemented baseline. The previously recorded G3 source-scan release hold remains unresolved. This implementation has not been released or deployed.
