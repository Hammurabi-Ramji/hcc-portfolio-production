# A-F009 — persisted users API remediation

Status: DONE (scoped executable acceptance). Folder: apps/web/app/api/users. Wave1.

The147-line seeded Map handler is replaced by a thin Node proxy. Added profile, avatar and dynamic item handlers under the explicitly granted users subtree. The shared Rust service now provides admin-only durable account list/create, owner/admin item reads, current-user profile reads/updates and truthful unsupported avatar upload. No schema, dependency, credential store or manifest is duplicated.

Eight production files are listed with byte-exact before/after hashes and per-file unified patches in source-manifest.json. Existing direct route/lib/auth files have byte snapshots; newly added files use /dev/null diff headers. Tests live permanently in apps/api/tests/users_http.rs. Root approved the narrow auth.rs transaction-revalidation helper lease; root alone updates registry, ledger and to-do.

## Diff and behavior

- users.rs: strict bodies and bounded positive pagination, cap100, literal search and single canonical envelope; required persisted flags and ISO strings. Normalizes email and optional username, hashes real credentials with shared Argon2id helper, generates cryptographically random256-bit IDs and commits users/profile together. SQLite unique constraints prevent duplicate/concurrent overwrite across instances.
- auth.rs: ValidSession.revalidate checks persisted hash/revocation/expiry/active and reloads identity/role on the caller's transaction. Creates/profile writes take immediate transactions and reauthorize inside them, including after password hashing. No token is exposed and no Store mutex is recursively acquired.
- lib.rs: serialized users router registration before shared fallback/boundary layers.
- four Next routes: use existing fixed-loopback proxy and centralized exact-Origin preflight. Dynamic IDs encodeURIComponent before construction, preventing slash injection into downstream path segments. GET item only matches existing caller contract; root confirmed no speculative item PUT.
- profiles: firstName,lastName,bio,website,location and avatar reference persist independently for each identity; omitted/null values preserve, empty strings clear. HTTP(S) references are validated but never fetched. Upload endpoint returns authenticated501; no fake storage success.
